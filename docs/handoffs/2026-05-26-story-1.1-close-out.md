## Os 3 patches detalhados (pra @dev backportar literalmente)

### Patch 1 — magic-link URL

**Arquivo:** `frontend/admin/app/api/auth/magic-link/route.ts`

```diff
- const link = `${env.ADMIN_PUBLIC_URL.replace(/\/$/, "")}/verify?t=${plaintext}`;
+ const link = `${env.ADMIN_PUBLIC_URL.replace(/\/$/, "")}/api/auth/verify?t=${plaintext}`;
```

Também atualizar o JSDoc no topo do arquivo:

```diff
- *   • Sends email via Resend with link to /verify?t={plaintext}.
+ *   • Sends email via Resend with link to /api/auth/verify?t={plaintext}.
```

**Por quê:** o handler que processa o token é GET `/api/auth/verify` (route handler), faz validação + set cookie + redirect server-side. A página `/verify` é só fallback de erro (quando user chega lá sem `?t=`).

---

### Patch 2 — CSP relaxada para Next App Router

**Arquivo:** `frontend/admin/next.config.ts`

```diff
  const csp = [
    "default-src 'self'",
-   "script-src 'self'" + (isProd ? "" : " 'unsafe-eval'"),
+   "script-src 'self' 'unsafe-inline'" + (isProd ? "" : " 'unsafe-eval'"),
    "style-src 'self' 'unsafe-inline'",
    ...
  ].join("; ");
```

**Por quê:** Next App Router faz streaming SSR e injeta scripts inline `<script>self.__next_f.push(...)` com a payload RSC. CSP estrita bloqueia. Resultado: hydration falha silenciosamente → onClick / dropdowns / fetch não funcionam, mas links HTML puros sim.

**Trade-off documentado:** `'unsafe-inline'` em script-src é menos seguro que nonce dinâmico. Risco aceitável pra MVP porque:
- Painel admin behind auth + nginx + 2-3 users
- Sem conteúdo de terceiros renderizado
- Sem input do usuário ecoado no DOM sem escape

**Backlog:** migrar pra nonce-based CSP (proxy.ts gera nonce → headers + injeta em scripts) na Story 1.6 ou em uma 1.1.1 dedicada de hardening. Anotar no MEMORY.md.

---

### Patch 3 — tsx em dependencies (runtime, não dev)

**Arquivo:** `frontend/admin/package.json`

```diff
  "dependencies": {
    ...
    "sonner": "^2.0.7",
    "tailwind-merge": "^3.6.0",
+   "tsx": "^4.22.3",
    "tw-animate-css": "^1.4.0",
    ...
  },
  "devDependencies": {
    ...
    "tailwindcss": "^4",
-   "tsx": "^4.22.3",
    "typescript": "^5"
  }
```

**Por quê:** o script `npm run seed:admin` usa `tsx` em runtime no container de produção. Dockerfile roda `npm ci --omit=dev` na stage `deps`, então tsx fica fora. Em prod, `npx tsx` tenta baixar e pede interação `y/n` que trava em STDIN não-interativo.

**Validar após patch:** `cd frontend/admin && npm install` (atualiza package-lock.json), depois `docker compose build admin-frontend` localmente se quiser, mas o build remoto vai pegar no merge automático.
